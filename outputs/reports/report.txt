# Bitcoin Price Prediction Using Machine Learning

## 1. Executive Summary

This project presents a complete machine learning workflow for short-term Bitcoin price prediction using historical market data. The dataset contains high-frequency Bitcoin market records at 1-minute intervals, including Open, High, Low, Close, Volume, and timestamp information.

The project follows a structured data science pipeline: data loading, initial inspection, exploratory data analysis, data cleaning, feature engineering, model training, model evaluation, and final prediction analysis. Several regression models were trained and compared, including Linear Regression, Ridge Regression, Lasso Regression, and ElasticNet Regression.

The final model was selected based on evaluation metrics such as R² Score, MAE, and RMSE. The main objective of this project is to predict the next 1-minute Bitcoin closing price using historical market data and machine learning regression models.

The prediction target is:

**Target variable: `Next_Close`**

This means the model uses the current and historical market information to estimate the closing price of the next time interval.

The project aims to:

* Analyze historical Bitcoin market behavior.

* Engineer meaningful features from raw OHLCV data.
* Train and compare multiple regression models.
* Evaluate model performance using regression metrics.
* Interpret prediction errors and model limitations.

This is a short-term forecasting project, not a long-term Bitcoin investment prediction system.

The EDA stage focused on understanding Bitcoin’s market behavior through price trends, volume patterns, volatility, returns, and feature relationships.

### Bitcoin Price Trend

The Bitcoin closing price showed a strong long-term upward trend, especially in later years. Early values were very low compared to recent price levels. This confirms that Bitcoin has experienced major long-term growth, but not in a smooth or linear way.

The price chart also showed several sharp corrections and high-volatility periods. This is important because it indicates that Bitcoin price behavior is highly dynamic and non-stationary.

### Trading Volume

Trading volume changed significantly over time and contained visible spikes. These spikes may represent periods of increased market participation, speculation, or reaction to major events.

Volume is important because it reflects market activity and liquidity. However, volume alone did not fully explain price direction.

### Price Distribution

The distribution of Bitcoin closing prices was heavily right-skewed. This is expected because early Bitcoin prices were very low, while later prices reached much higher levels.

A log transformation of price values was also explored. The log-transformed distribution appeared more balanced and helped reduce the effect of extreme price values.

### Return Distribution

The return distribution was concentrated around zero. This means that most 1-minute price movements were small. However, the distribution also contained extreme values, which is typical in financial markets.

This shows that Bitcoin returns are not normally distributed and may contain sudden large movements.

### Volatility Analysis

Volatility was calculated using the price range within each interval:

```text
Volatility = High - Low
```

Rolling volatility was also calculated to observe market instability over time. The analysis showed that Bitcoin volatility changes significantly across different periods. High-volatility periods tend to cluster, which is a common behavior in financial time series.

### Moving Averages

Moving averages were used to smooth short-term price fluctuations and observe trend behavior.

Created moving averages:

The moving average plots showed that short-term averages reacted faster to market changes, while longer-term averages provided a smoother view of the overall trend.

### Correlation Analysis

The correlation heatmap showed very high positive correlations among `Open`, `High`, `Low`, and `Close`.

This is expected because OHLC prices are measured within the same time interval and tend to move together. However, this also indicates possible feature redundancy, which is important to consider during modeling.

### Monthly and Hourly Patterns

Monthly volatility and volume analysis showed no strong seasonal pattern. This suggests that Bitcoin market behavior is driven more by market conditions, investor sentiment, and external events than by specific calendar months.

Hourly volatility was also analyzed to explore potential intraday behavior. Since Bitcoin trades 24/7, time-based patterns may still reflect global market activity differences.

## 6. Feature Engineering

Feature engineering was one of the most important stages of the project. The goal was to transform raw OHLCV data into model-ready variables that could better represent market behavior.

### Time-Based Features

The `Date` column was used to extract numerical time features:

| Feature   | Description       |
| --------- | ----------------- |

`Rolling_Volatility` was created using the rolling standard deviation of returns. This feature captures recent market instability.

### Lag Features

Lag features were added to allow the model to use previous market values:

| Feature        | Description                |

Lag features are especially important in time-series modeling because they provide historical context.

### Target Variable

The target variable was created as:

Next_Close = next interval's Close price

This allows the model to predict the next 1-minute Bitcoin closing price.

## 7. Machine Learning Methodology

The project used a regression-based machine learning approach. The final model-ready dataset was split using a time-based train-test split.

### Train-Test Split

The dataset was split chronologically:

| Split        |   Portion |
| ------------ | --------: |
| Training set | First 80% |
| Test set     | Final 20% |

This was important because the data is time-series data. A random split could introduce data leakage by allowing future observations to appear in the training set.

### Scaling and Pipeline

The models were built using scikit-learn pipelines. Linear models are sensitive to feature scales, so `StandardScaler` was used before model training.

The pipeline structure was:

```text
StandardScaler → Regression Model
```

This ensures that scaling is fit only on the training data and then applied consistently to the test data.

### Models Used

Four regression models were trained and compared:

| Model                 | Reason for Use                           |
| --------------------- | ---------------------------------------- |
| Linear Regression     | Baseline interpretable regression model  |
| Ridge Regression      | Regularized linear model with L2 penalty |
| Lasso Regression      | Regularized linear model with L1 penalty |
| ElasticNet Regression | Combination of L1 and L2 regularization  |

Tree-based models such as Random Forest and Gradient Boosting were initially considered but excluded from the final comparison because the full high-frequency dataset was computationally expensive to train on.

### Model Descriptions

#### Linear Regression

Linear Regression estimates a linear relationship between input features and the target variable. It was used as the baseline model. In this project, it performed best overall.

Advantages:

* Fast to train.
* Easy to interpret.
* Strong baseline for regression.

Limitations:

* Assumes mostly linear relationships.
* May struggle with highly non-linear market behavior.

#### Ridge Regression

Ridge Regression adds L2 regularization to reduce overfitting and control large coefficients.

Advantages:

* Useful when features are highly correlated.
* More stable than ordinary linear regression in some cases.

Limitations:

* Does not eliminate features.
* Still assumes a mostly linear relationship.

#### Lasso Regression

Lasso Regression uses L1 regularization and can shrink some coefficients to zero.

Advantages:

* Can perform implicit feature selection.
* Useful when some features may be less important.

Limitations:

* Can be sensitive to the regularization strength.
* May underperform if many features are useful.

#### ElasticNet Regression

ElasticNet combines L1 and L2 regularization.

Advantages:

* Balances Ridge and Lasso behavior.
* Useful when there are many correlated features.

Limitations:

* Requires tuning `alpha` and `l1_ratio`.
* In this project, it produced the highest error among the tested models.

## 11. Limitations

This project has several important limitations:

1. **Short prediction horizon**
   The model predicts the next 1-minute closing price. This is not the same as predicting long-term Bitcoin trends.

2. **Historical price data only**
   The model uses OHLCV data and engineered features derived from historical prices. It does not include news, social media sentiment, macroeconomic indicators, regulations, or market psychology.

3. **High market volatility**
   Bitcoin is highly volatile. Sudden price movements, crashes, or pumps may not be predicted accurately by a model trained only on historical price data.

4. **Potential overfitting risk**
   Very high R² values in financial time-series data should be interpreted carefully. The high score is partly due to the short time horizon and strong similarity between consecutive price values.

5. **Limited validation strategy**
   The project used a time-based train-test split, which is appropriate. However, walk-forward validation or time-series cross-validation could provide a more robust evaluation.

6. **No external market context**
   The model does not understand real-world events, exchange-specific liquidity, investor sentiment, or macroeconomic shocks.
